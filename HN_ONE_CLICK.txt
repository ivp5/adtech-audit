Author here. The IAB Tech Lab's ads.txt and sellers.json specs are the
"supply-chain transparency" framework underneath programmatic
advertising. I cross-referenced 76,425 publishers' ads.txt files
against 739 SSP sellers.json registries — 28.77M total rows, 6.56M of
which are DIRECT-typed.

Findings, ranked by defensibility:

1. The framework's verification primitive returns 1 bit per claim
   ("seller_id exists in registry: yes/no"). The registry encodes
   ~17.77 bits per row. The gap is by design; whether it's a problem
   depends on whether verification should have returned more than the
   spec mandates.

2. 26.8% of corpus DIRECT claims are PHANTOM (no registry record at
   all anywhere). N=100 random-sample re-verified against current live
   registries: 95.6% confirmation. Spec-violating subset.

3. SpotX (Magnite) — 7,942 publishers carry DIRECT phantom claims;
   spotxchange.com/sellers.json has returned zero bytes for 5+ years.
   Wayback has zero JSON-200 snapshots. Largest single-SSP framework
   failure documented.

4. ~10,966 publishers carry the same 4 phantom SmartAdServer
   seller_ids (4012/4071/4073/4074, none in the current registry).
   Composition is mixed: ~20% piracy/streaming, ~80% legitimate
   publishers across many TLDs.

5. Multiple ad-tech rebrands (Sovrn, Magnite, SpotX) serve catch-all
   HTML at /sellers.json on the canonical domain while the legacy
   domain quietly hosts the registry. IAB Tech Lab's own sellers.json
   path returns HTTP 200 + HTML.

Reproducer (stdlib Python, no project deps):

    git clone https://github.com/ivp5/adtech-audit
    cd adtech-audit
    python3 tools/reproducer/verify_template_carrier.py mangafire.to
    # → 7/7 SSPs with claims; 845 DIRECT+RESELLER; 328 phantom + 517 mismatch
    python3 tools/reproducer/verify_template_carrier.py nytimes.com
    # → 0/7 SSPs with claims. Clean.
